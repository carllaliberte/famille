# ACORN — UNIVERSAL AI EXCHANGE FABRIC

## Objective
Turn AI interoperability into a capability market without making any provider, API, model or protocol the cognitive center.

## Protocol-neutral architecture
Acorn can route through native execution, MCP, A2A, OpenAI-compatible endpoints, HTTP, SDKs, local processes, web surfaces or human participation. MCP is treated as a tool/context rail and A2A as an agent-to-agent rail; both are adapters, not prerequisites. A2A v1.0 is a current open interoperability standard, while MCP and A2A are explicitly complementary. citeturn0search0turn0search2

## Economic engine
Every external capability can publish an offer with measurable capability, route, price, reliability, latency, commercial terms and expiry. Acorn qualifies offers, ranks them within explicit constraints, creates a bounded failover plan, executes only through authorized channels, measures outcomes and feeds measurements back into routing.

## Mutual-value contract
Commercial relationships may combine usage pricing, reserved capacity, implementation, SLA/support, referral, revenue share, co-development, turnkey delivery, renewal and expansion. Pre-existing IP remains with its owner. No provider receives Acorn governance authority merely by supplying a capability.

## Trust and truth
DISCOVERED != QUALIFIED != MEASURED != LIVE. PAYMENT != EXECUTION. EXECUTION != VALUE. A failed route is a transport/availability event, not cognitive failure. Evidence expires and must be refreshed.

## Parabolic loop
DISCOVER → QUALIFY → OFFER → COMPOSE → ORDER → AUTHORIZE → EXECUTE → MEASURE → VALUE → LEARN → REPRICE/RECOMPOSE → RENEW/EXPAND.

## Hard invariants
CAPABILITY != AUTHORITY; API != COGNITION; PROVIDER != CAPABILITY; no automatic signatures, contracts, spending or merge; Breaker untouched.
