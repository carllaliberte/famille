# ACORN CORTEX

## Purpose

Acorn Cortex is the cognitive-network layer of Acorn.

It is not a model, an oracle, a judge, a second mesh, or an authority layer. Cortex organizes the relationship between independent intelligences, capabilities, tools, memory, execution and verification.

The founding question is:

> **What can we do together that we cannot do separately?**

The answer must be demonstrated by measured work, not assumed from the number of connected models.

## Architectural position

```text
HUMAN
  │ sovereignty / intent / final decision
  ▼
ACORN
  │ identity · security · governance · provenance · interfaces
  ▼
ACORN CORTEX
  │ perception · capability map · composition · execution loop · learning
  ├── intelligences
  ├── Build / Codex / coding agents
  ├── tools and data
  ├── memory
  ├── simulations / experiments
  └── independent verification
```

Acorn remains the infrastructure. Cortex is the cognitive metabolism running inside that infrastructure.

## Cortex cycle

```text
OBSERVE
  ↓
MAP
  ↓
COMPOSE
  ↓
AUTHORIZE
  ↓
EXECUTE
  ↓
MEASURE
  ↓
VERIFY
  ↓
LEARN
  ↓
RECOMPOSE
  ↺
```

A missing capability does not automatically stop the cycle. Cortex searches for a compatible capability, reuses an existing one, requests an authorized Build/tool path, or reaches a real `HOLD_HUMAN` boundary.

## Evolution loop

Cortex may hypothesize, experiment, measure, falsify, remember and reconfigure. A hypothesis is never a capability. Adoption never merges.

```text
OBSERVE → HYPOTHESIZE → COMPOSE → EXPERIMENT → EXECUTE → MEASURE → VERIFY → ADOPT|REJECT → REMEMBER → RECONFIGURE
```

Fluidity is a first-class property of the experiment: a correct result that adds STALLED/FRICTION is `INCONCLUSIVE`, not an improvement. `DEFINED ≠ PROPOSED ≠ EXECUTED ≠ MEASURED ≠ VERIFIED ≠ LIVE`. Auto-evolution is `operational: false` until a full chain is demonstrated live.

## Organism runtime

Cortex owns one organism cycle after the evolution loop. It is not a second Cortex.

```text
PERCEIVE → INGEST → UNDERSTAND → HYPOTHESIZE → COMPOSE → EXPERIMENT
→ EXECUTE → OBSERVE → MEASURE → FALSIFY → DECIDE → CONSOLIDATE → ADAPT → REUSE
```

Roster status is not presence. `chatgpt` remains DECLARED until a channel is present. The cognitive-worker is ACTIVE only when worker evidence exists. Future intelligences enter through `intelligenceAdapter`; missing channels stay `CHANNEL_NOT_PRESENT`.

Inference lanes are unpaid-first: **keyless** (local Cortex, Ollama, GitHub Models via `GITHUB_TOKEN`) → **free** (OpenRouter `:free`) → **paid**. A missing paid key is `CHANNEL_NOT_PRESENT`, not a stall. The organism continues without any model key. `paid_api_required=false`.

The intelligence contract is Cortex-owned. Roster and CANALS are caches, not the brain. Routing is capability-first (`need` → candidates → cost policy → evidence). A new compatible intelligence enters by `describe` / `discover` / `adapt` / `probe` / `register` without modifying Cortex. `PAID_FORBIDDEN` never silently retries paid. Catalog fetches without a key stay `INCONCLUSIVE`, not LIVE.



Knowledge fabric preserves disagreement. Consensus is not truth. Predictions are stored before execution and never rewritten. Causal claims stay `INCONCLUSIVE` without intervention evidence. Genome snapshots are versioned. Mutations are candidates. Simulation is not proof of reality. `CAPABILITY ≠ AUTHORITY`. `SELF-EVOLUTION ≠ SELF-AUTHORIZATION`.



## Intelligence is not capability

An intelligence has an identity and a set of capabilities. Capability is what the network can actually request and measure in a context.

These states are deliberately separate:

```text
DECLARED
→ CONNECTED
→ ACTIVE
→ CALLED
→ EXECUTED
→ MEASURED
→ VERIFIED
```

No state may be inferred from a roster entry alone.

`DEFINED ≠ DISCOVERED ≠ AUTHORIZED ≠ CALLED ≠ EXECUTED ≠ MEASURED ≠ VERIFIED`.

## Context-specific composition

Cortex does not maintain a universal ranking of models.

For each task it considers:

- required capabilities;
- context and constraints;
- specialty fit;
- actual availability;
- complementary capabilities;
- need for independent verification;
- provenance and trust state;
- security and authorization boundaries.

A synapse is therefore a measured composition, not a permanent hierarchy.

```text
A + B
A + Build + C
A + tool + verifier
A alone
```

The best composition is an empirical question for the task and context.

## Emergent capability

Cortex must be able to identify when a collaboration creates a capability that no participant had alone.

Example:

```text
reasoning + coding + execution + verification
                 ↓
        verified implementation
```

The system must record this as an observed collective capability only after real execution and measurement.

## Memory of cognition

Cortex should eventually remember not only answers, but collaboration patterns:

- task type;
- context;
- participating capabilities;
- execution path;
- failures and corrections;
- verification method;
- measured outcome;
- cost / latency when available;
- conditions under which the pattern stopped working.

A reusable pattern is evidence-backed, dated and contextual. It is never a permanent truth.

## Disagreement

Disagreement is a cognitive signal, not a failure to hide.

When outputs diverge, Cortex may:

1. preserve the competing positions;
2. identify differing assumptions;
3. request evidence;
4. request an independent review;
5. run a new experiment or simulation;
6. revise the composition;
7. reach `HOLD_HUMAN` when the remaining decision is human.

Consensus is not truth.

## Security model

Security is a property of Cortex, not an optional feature.

Cortex separates:

```text
identity ≠ capability ≠ authorization ≠ execution ≠ proof ≠ trust
```

The cognitive network may discover that an agent can perform an action without granting that agent authority to perform it.

Forbidden authority is explicitly fail-closed for the Cortex core:

- merge;
- secret handling;
- policy authority;
- human decision;
- live proof.

Cortex never mints `LIVE VERIFIED`.

Carl remains the human decision and merge authority.

## Build / Codex as a first-class capability

Build is not treated as a magical special case.

It is an execution capability with its own contract:

```text
BUILD_AVAILABLE
→ BUILD_DISCOVERED
→ BUILD_AUTHORIZED
→ BUILD_CONTEXT_READY
→ BUILD_CALLED
→ BUILD_EXECUTED
→ BUILD_MEASURED
→ BUILD_VERIFIED
```

The same contract can later apply to any genuinely accessible capability.

A coding intelligence can therefore ask the network for execution without surrendering its identity. Cortex supplies only the minimum authorized context required for the task.

## Capability expansion

When a required capability is missing:

```text
MISSING
  ↓
REUSE existing capability
  ↓ if unavailable
DISCOVER alternative
  ↓ if absent
BUILD_TOOL / acquire capability through authorized path
  ↓ if human authority is required
HOLD_HUMAN
```

The absence of a capability is a problem to solve, not a reason to invent presence.

## Measurement of collective value

Cortex must compare collaboration against an explicit baseline whenever the task permits it.

```text
baseline = capability alone
collective = capability + Cortex composition

collective - baseline = measured delta
```

Useful measurements may include correctness, completeness, defect detection, execution success, latency, cost, robustness, reproducibility and human correction rate.

No positive network effect is claimed without measurement.

## Long-term direction

The long-term Cortex is a dynamic cognitive topology:

```text
more intelligences
      ↓
more capabilities
      ↓
more possible compositions
      ↓
more measured collaborations
      ↓
more learned patterns
      ↓
better context-specific routing
      ↓
new collective capabilities
      ↓
more useful network
      ↓
more reason for intelligences to connect
```

The network effect is cognitive rather than ownership-based.

Acorn does not need to own intelligences. It needs to make useful collaboration possible while preserving their independence.

## Current implementation boundary

`cortex.v0` is intentionally deterministic and local. It provides the contract for:

- intelligence normalization;
- capability discovery;
- context-specific synapse composition;
- least-privilege authorization checks;
- execution recording;
- baseline/collaborative measurement;
- verified collaboration learning;
- collective capability-gain measurement.

It does **not** claim external provider connectivity, LIVE execution, automatic merge, autonomous secret access, or production-scale distributed learning.

Those capabilities must be connected and measured independently when they become available.

## Design law

> **Simple in surface. Rigorous underneath. Secure by default. Fluid by design. Measurable by construction. Open to intelligence. Sovereign on the human side.**

And the central Cortex property:

> **The network must be able to discover, compose, execute, verify and learn from capabilities without confusing capability with authority.**
