# ACORN — Continuous Evolution Fabric

Les certitudes ont une date de fin.

## Purpose

Acorn must not merely maintain itself. It must continuously improve the relationship between human intent and measured reality.

Permanent loop:

WORLD → OBSERVE → GAP → DISCOVER → COMPARE → COMPOSE → SIMULATE → PROPOSE → BUILD/EXECUTE → MEASURE → FALSIFY → VERIFY → REGISTER → REUSE → OBSERVE

This is a conductor over existing Acorn fabrics, not a second runtime.

## Evolution surface

The frontier covers:

- customer outcomes and friction;
- products and offers;
- market demand and opportunities;
- capabilities and compositions;
- intelligences and providers;
- connectors and real-world integrations;
- projects and execution;
- architecture and code;
- quality and evidence;
- security and resilience;
- performance and resource use;
- economics and value;
- knowledge and reusable assets;
- real-world execution;
- unknown spaces that require discovery.

These 18 names are DECLARED surfaces. A declaration is not an observation.

`observeDeclaredSurfaces` emits one row per declared surface from the MAIN snapshot (pull requests + workflow runs). PROJECT and CODE may be OBSERVED from that snapshot. Every other declared surface stays `NOT_MEASURED` / `UNKNOWN` until evidence exists.

`observations: []` is a lie: it pretends the surfaces were looked at and nothing was there.

Carte juge absente (quelle / temoin / epsilon>0 / horizon jour) → MODE classique. The hole is named. It is not filled. Preview ≠ quittance. A GitHub 200 is not a seal.

DECLARED ≠ OBSERVED ≠ MEASURED ≠ VERIFIED ≠ LIVE.

## Gap-first operation

EXPECTED vs OBSERVED → GAP → CAUSE → OPTIONS → COMPARISON → ACTION → MEASUREMENT

Unknown is not silently treated as failure or permission:

UNKNOWN → RESEARCH TARGET

A missing capability becomes a discovery problem:

NEED → GAP → DISCOVER → COMPOSE → BUILD/CONNECT → VERIFY → CAPABILITY

## Best-known result

Acorn compares measured candidates inside explicit scope.

BEST_KNOWN_IN_SCOPE is allowed.

BEST_KNOWN_IN_SCOPE ≠ GLOBAL_BEST

## Compounding

A verified outcome may become reusable capability only when provenance, rights, current evidence and expiry-aware status support the reuse.

PROJECT → EXPERIENCE → EVIDENCE → KNOWLEDGE → CAPABILITY → PRODUCT → NEW PROJECT

## One coherent chantier

Evolution absorbs maintenance findings and frontier opportunities into one portfolio whenever possible.

CURRENT MAIN → RECOVER → RECOMPOSE → EVOLVE → TEST → FALSIFY → MEASURE → VERIFY → ONE PR → CARL MERGE

## Human sovereignty

The fabric may discover, compare, compose, propose, build and measure.

It may not:

- grant itself authority;
- merge;
- spend;
- sign;
- publish;
- bypass the breaker;
- invent LIVE/VERIFIED/payment/revenue/customer-value claims.

CAPABILITY ≠ AUTHORITY

LEARNING ≠ AUTHORITY

BUILD ≠ MERGE

CODE_PRESENT ≠ TESTED ≠ EXECUTED ≠ MEASURED ≠ VERIFIED ≠ LIVE

## Continuous property

There is no final static state.

After every verified cycle:

WORLD(t+1) → OBSERVE → FIND NEXT GAP → IMPROVE

The objective is continuous, evidence-bearing improvement under permanent human sovereignty.
