# ACORN — API-OPTIONAL FLUID COGNITION\n\nA brain does not require an API to think. Acorn therefore treats an API as a transport or adaptation rail, never as a prerequisite for cognition.\n\n## One fabric\n\nThe primary object is a capability. A capability can flow through IN_PROCESS, MEMORY, FILE, STDIO, LOCAL_PROCESS, SOCKET, DEVICE, HUMAN, FEDERATED, WEB or API substrates. The router selects the least-friction viable substrate from observed capability and availability.\n\nAPI failure is a transport failure, not a cognitive failure.\n\n## Inter-company economy\n\nCompanies keep their systems, authority and assets. They expose capabilities under mutually beneficial agreements covering capability access, compute/resource exchange, revenue share, referral, co-development, turnkey delivery, white-label, support, renewal and expansion.\n\nPricing, quality, latency, availability, reliability and measured value can be continuously compared. Signed commercial terms cannot be silently changed.\n\n## Permanent mode\n\nDebug is continuously enabled as observation: path choice, latency, failure, fallback and evidence are recorded without becoming authority.\n\nTruth constraints: API optional; provider replaceable; capability primary; CAPABILITY != AUTHORITY; DEFINED != EXECUTED; no fake LIVE or VERIFIED; no automatic contracts, spending, signatures or merges; Breaker immutable and untouched.\n\nEconomic flywheel: NEED → CAPABILITY → COMPOSITION → OFFER → AGREEMENT → EXECUTION → VALUE → REVENUE → LEARNING → NEW CAPABILITY.\n
