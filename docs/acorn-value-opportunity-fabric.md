# ACORN — Continuous Value & Opportunity Fabric

## Objective
Make Acorn broadly usable by the public and developers while recovering commercial infrastructure costs from organizations automatically, without creating a specialist-only cognitive class.

## Access
- Public: open/free where hosting economics permit.
- Developers: open/free core access.
- Community/open-source: open/free core access.
- Researchers: open or sponsored according to measured resource cost.
- OpenAI/ChatGPT: strategic partnership profile.
- Grok/xAI: strategic partnership profile.
- Businesses/enterprises: commercial usage contributes to infrastructure costs.

Profiles are policy, not identity. Acorn remains provider-neutral.

## Value loop
DISCOVER → QUALIFY → MEASURE → ADAPT → PILOT → VERIFY → PACKAGE → OFFER → OBSERVE → LEARN

## Automatic recovery
USAGE → MEASUREMENT → BILLING EVENT → PAYMENT RAIL → SETTLEMENT → RECEIPT → EVIDENCE

Acorn may accept crypto assets when a payment rail actually supports and verifies them. It must not claim universal support for every cryptocurrency without evidence. Automatic collection is distinct from automatic external spending.

## Customer experience
A person should arrive with a problem, not need specialist knowledge. Acorn should explain what it can do, evidence, uncertainty, cost, data handling, portability, and failure behavior. For businesses: measure first, bill automatically, explain clearly.

## Invariants
ACCESSIBILITY ≠ SPECIALIST PRIVILEGE
CAPABILITY ≠ AUTHORITY
Carl remains human authority. Commercial automation cannot merge code, change governance, authorize arbitrary spending, or redefine constitutional rules.
