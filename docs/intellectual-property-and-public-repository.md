# ACORN — INTELLECTUAL PROPERTY / PUBLIC REPOSITORY
## Reality
A public GitHub repository cannot technically prevent someone from cloning, forking, copying or archiving code that is publicly accessible. No workflow can truthfully guarantee otherwise.

## Protection strategy
- Keep Acorn source under a proprietary, explicit license for new material where legally appropriate.
- Preserve copyright notices and authorship/attribution.
- Mark protected modules as Acorn proprietary.
- Separate public specifications, SDK surfaces and documentation from protected implementation where practical.
- Never publish secrets, credentials, private customer data or proprietary partner material.
- Use signed releases and provenance/evidence for authorship.
- Monitor forks/derivatives and document provenance.
- Where a previous version was MIT-licensed, recognize that license grants cannot simply be retroactively revoked for copies already distributed under it.

## Collaboration credit
Acorn can explicitly record the human/AI collaboration history in provenance metadata: Carl Laliberté = owner/merger authority; AI systems = collaborators/tools for analysis and implementation. This preserves the history without transferring ownership or authority to an AI.

## Policy
CAPABILITY ≠ AUTHORITY.
PUBLIC ≠ COPY-PERMISSION-FREE.
CODE PRESENT ≠ LEGAL EXCLUSIVITY.
