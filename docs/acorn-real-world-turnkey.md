# ACORN — Real-World Turnkey Completion

This module is the **single composition contract** for the existing customer, commercial, connection, intelligence, execution and evidence fabrics.

It does not create a second runtime.

## Customer loop

`CUSTOMER → PROBLEM → PROJECT → CAPABILITIES → REAL CONNECTIONS → OFFER → CHECKOUT → PAYMENT_OBSERVED → AUTHORIZATION → EXECUTION → OBSERVATION → VERIFICATION → DELIVERY → VALUE → RENEWAL → EXPANSION`

The runtime distinguishes:

- configured from authenticated;
- authenticated from connected;
- connected from executable;
- executable from measured;
- measured from verified;
- verified from live.

It also preserves:

- `CAPABILITY ≠ AUTHORITY`
- `PAYMENT ≠ EXECUTION`
- `PREVIEW ≠ RECEIPT`

The module is deliberately **provider-neutral**. A connector is real only when its measured state says so. A secret name, adapter, mock, or declaration cannot create LIVE.

## Immediate operational purpose

The live runtime can use this contract to answer one question for every customer project:

> **What is the next real-world action required to move this project forward?**

If the answer is a missing connector, the customer experience should expose that requirement rather than pretending execution is available.

If payment is observed but delivery is not verified, the next action is delivery verification.

If value is delivered but not measured, the next action is customer-value measurement.

If everything is evidenced, the cycle moves toward renewal and expansion.

Human authority remains explicit for consequential external effects.
