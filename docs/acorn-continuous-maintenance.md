# ACORN Continuous Maintenance Fabric

## Purpose

Acorn maintenance is one continuous organism, not a collection of manual micro-chants.

The permanent loop is:

`OBSERVE → AUDIT EVERYTHING → CLASSIFY → RECOVER USEFUL WORK → RECOMPOSE ON CURRENT MAIN → REPAIR → TEST → FALSIFY → MEASURE → VERIFY → ONE PR → CARL MERGE → REOBSERVE`

## Scope

The fabric audits, in one pass:

- every open pull request;
- stale and divergent branches;
- failed workflow runs;
- regressions and broken checks;
- missing capabilities;
- quality/evidence drift;
- transient/environment failures;
- explicit human boundaries.

It converts all actionable findings into **one coherent repair portfolio**.

## Safety contract

`CAPABILITY ≠ AUTHORITY`

The maintenance organism may diagnose, consolidate, repair, test and prepare a PR. It may not:

- merge;
- grant itself authority;
- bypass the breaker;
- fabricate LIVE/VERIFIED/EXECUTED/payment/revenue claims;
- use a stale branch as a merge base;
- cross human secret/payment/contract/signature/publication boundaries.

## Relationship to existing Acorn

This is a fabric over the existing:

- Codex autonomous worker;
- self-heal runtime;
- continuous work engine;
- quality fabric;
- best-known-result/adaptive market fabric;
- intent → reality compiler;
- universal value fabric.

It is **not** a second runtime, second Cortex, second market, second evidence system or second authority system.

## Desired operational behavior

If five defects exist, Acorn does not create five unrelated repair requests.

It creates one portfolio:

`CURRENT MAIN → RECOVER → RECOMPOSE → REPAIR → TEST → FALSIFY → MEASURE → VERIFY → ONE PR`

If a secret, payment, contract, signature, protected merge or other human decision is required, the system stops at `WAITING_HUMAN` with preserved evidence.

## Truth

`CODE_PRESENT ≠ TESTED ≠ EXECUTED ≠ MEASURED ≠ VERIFIED ≠ LIVE`

A successful worker run is not itself proof that the resulting system is LIVE.
