# ACORN — Complete Optimal Delivery

Acorn now defines a complete project as more than code.

A project is complete only when its declared objective, acceptance criteria, constraints, required connections, execution, delivery, evidence, measurements, verification and customer-value outcome are accounted for.

## Optimal forever

"Optimal" is treated as a continuous scientific/economic state, never as an eternal assertion:

OBSERVE → DISCOVER → COMPARE → COMPOSE → DELIVER → PROVE → BENCHMARK → OPTIMIZE → REDELIVER → OBSERVE

The system selects the **best known result in an explicit scope**, using measured evidence. When a better measured result appears, the previous result becomes superseded and the new result becomes the current candidate.

There is no honest final "perfect forever" state. The system can instead maintain a permanent improvement obligation.

## Definition of complete

COMPLETENESS requires, within declared scope:

- customer objective
- acceptance criteria
- constraints and jurisdiction
- required capabilities
- required connections
- execution
- delivery
- evidence
- measurements
- verification
- outcome
- customer value
- rights/provenance
- expiry/freshness
- operational recovery path

## Optimization dimensions

Customer value, quality, reliability, latency, cost, margin, security, privacy, evidence, freshness, maintainability, reusability, interoperability, simplicity, accessibility, resilience, scalability, sustainability, time-to-value and completeness.

## Human sovereignty

Acorn can discover, compare, compose, simulate, measure and propose. Consequential actions remain explicitly authorized through existing server and human controls.

The system must never manufacture a customer, payment, revenue, LIVE status, verification or global optimum.

## The product principle

The product delivered by Acorn is not the code alone.

It is a **measurable result**, with its evidence, provenance, rights, operational state, value and continuous improvement path.
